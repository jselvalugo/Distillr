Build a clean, minimal, production-ready web application called SiteClean Pro for cleaning companies in Florida. This is an operations + compliance + proof-of-service system that helps owners answer three daily questions:

Who is scheduled to clean today?

Are they cleared/allowed to be on site?

Was the job completed—and can we prove it?

The product must feel calm, professional, and “boringly reliable.”

Design & UX Principles (Non-Negotiable)

Visual style: clean, minimal, professional

Primary palette: white background with orange accents

Buttons: white fill with thin orange gradient outline (subtle, modern), not heavy fills

Use orange gradient lines sparingly for:

button outlines

dividers / section separators

focus states

Typography: modern and readable (e.g., Inter)

No clutter, no excessive widgets, no noisy dashboards

Pages should be tablet-friendly and fast

Prefer simple pages over modals; use modals only when essential

Every action must clearly confirm success/failure

Technical Expectations (Replit-Friendly)

Frontend: React (clean component structure)

Backend: Node.js + Express (or FastAPI if you prefer Python)

DB: SQLite for MVP (upgrade path to Postgres)

Auth: session/JWT

File storage:

local storage for MVP

design storage abstraction so it can move to S3 later

Use environment variables for secrets

Keep code readable and boring (good boring)

Guardrails / Positioning

Use language like: “track,” “monitor,” “status,” “records.”
Avoid: “certify,” “guarantee,” “verify.”

Include footer disclaimer:
“This system provides administrative visibility only. Final compliance and access decisions remain the responsibility of the customer.”

MVP Success Criteria

Owner can see “Who’s working today?” in under 5 seconds

Dispatcher can schedule jobs without confusion

Completion reports reduce disputes with clients/HOAs/STR hosts

Compliance reminders reduce last-minute jobsite denials

UI feels calm, clean, and trustworthy in orange/white

Final Instruction

Bias toward clarity over cleverness, restraint over features, and trust over theatrics.
Expand the data model, not the visual noise. Keep the UI minimal and elegant with orange gradient outlines around buttons.
